# Forest 4K 글자 — 엔진 글자 경로 조사 (2026-11-21, 「4K 글자」 갈래)

주소는 지도 로더판 `Forest.exe`(코드 구역이 사용자 판 f618b6… 와 같음) 기준. 정적 근거는 capstone 역어셈블(`tools\fdis.py`), 실행 근거는 숨긴 시험의 탐침 기록(`Y:\AI\claude-work\hitext\p1\hitext_probe1.log`·`hitext_probe3.log`, 탐침 소스 `tools\qol_hitext_probe.cpp.txt`).

## 1. 한눈에

- 글자는 **한 글자 = 스프라이트 하나**다. 엔진이 글자마다 `CreateFontA` + `GetGlyphOutlineA(GGO_GRAY8)` 로 BlackBox 크기 32비트 표면을 만들고, 장면 합성기가 그 스프라이트들을 다른 그림과 같이 z 순으로 앞 화면 판(800×600)에 섞는다. 「글자 판」 같은 따로 된 층은 없다.
- 대사: **굴림(Gulim) 21px**, 모드 3(GRAY8 안티에일리어스), 흰색, 외곽선·그림자 없음. 세이브 화면 날짜: 굴림 16px, 모드 3, 갈색 `0x5e3619`(마우스를 올린 칸은 흰색으로 다시 만들고 파란 강조가 그 위에 덮인다).
- 한 글자씩 찍기 = 그 글자 스프라이트를 혼합 방식 2(전체 불투명도 +0x2c)로 63→127→191→255 네 단계 페이드한 뒤 방식 0 으로.
- 글자 자리 = 부모 좌표(offset) + 스프라이트 사각형(+0x3c). 대사 첫 줄 왼쪽 x 176, 줄 간격 26(글꼴 높이 21 + 5), 고정폭(2바이트 글자 21, 1바이트 글자 10).
- 메시지 창 숨김(Shift)·쪽 넘김·장면 바뀜은 글자 스프라이트를 안 그리는 것으로 나타난다. 설정·세이브 화면은 장면 묶음의 다른 칸이라 그동안 대사 장면은 합성되지 않는다. 지도는 지도 DLL 이 창에 직접 그린다(엔진 창 BitBlt 건너뜀).
- 화면 전환 효과는 앞 판을 `+0xa4` 로 복사해(0x43d490) 섞는다 → 엔진 판 자체는 손대지 않는 설계를 골랐다(3절).

### 2-2. 글리프 만들기

- `0x444ce0` = 글리프 객체 vtable[0](주 vtable `0x45ca90`, 가상 바탕 vtable `0x45c9a0`): `0x4452b0` 을 부른 뒤 `+0x24=1, +0x26=0, +0x28=0, +0x2c=0`.
- `0x4452b0`(thiscall, this = 글리프 객체, `ret 0x20`) 인자: `(ch, 높이, 글꼴 이름, 세로, 모드, 굵게, 기울임, 색)`. `모드 & 0xffff` 로 나눈다(`0x4452c3` 점프표 `0x4453cc`).

| 모드 | 함수 | 방식 |
|---|---|---|
| 0(그 밖) | 0x4453e0 | GGO_BITMAP(흑백). 세로면 「@」+이름 글꼴과 90° 행렬. 켜진 칸 = 색(알파 바이트 0), 꺼진 칸 = 0xff000000 |
| 1 | 0x445760 | GGO_GRAY8 → RGB 에 v·255/64>>3, 혼합 방식 0x16(따로 섞는 회색 판) |
| 2 | 0x445ab0 | GGO_BITMAP |
| 3 | 0x445e70 | **GGO_GRAY8**. 표면 = BlackBox, `0x42e100(색)` 으로 단색 채우고 알파 바이트만 `~(v·255/64)` (= 투명도). 전진폭: 2바이트 글자 = 높이, 1바이트 = 높이/2(`0x446019`~). 끝에 `0x42e170(0)`·`0x42e310(0)`(혼합 방식 +0x28·+0x30 = 0) |
| 4·5 | 0x446100·0x446360 | GetTextExtentPoint32A + TextOutA |

- 글리프 객체 칸: `+8` GLYPHMETRICS(+8 BlackBoxX, +0xc BlackBoxY, +0x10 원점 x, +0x14 원점 y, +0x18 전진 x(u16), +0x1a 전진 y). 표면(가상 바탕 하위 객체 = 객체 + 4 + `[[객체+4]+4]`): `+8` 화소, `+0x14` 너비, `+0x18` 높이, `+0x68` CRITICAL_SECTION. 화소는 위→아래, 피치 = 너비×4.

### 2-3. 글 넣기·배치(텍스트 객체)

- 메시지 창 `[0x46630c]` 의 `+0x68` = 텍스트 객체. 글 넣기 `0x4127e0` → `0x438770(str)` → `0x438790`(제어 문자 풀기 + 글자마다 `0x438ce0`) → `0x4391a0`(배치).
- `0x438790`: 2바이트 글자는 그대로, `^` 뒤 코드로 상태를 바꾼다 — 색 코드 표(`0x438916`~: 0x000000, 0xffffff, 0x79f1f2, 0xb73333, **0xffde00**(노랑), 0xf8b1ef, 0x7fdfa5, 0xc187f6, 0xfaa25a, 0x2020ff, 숫자는 `[+0xe8+i·4]`), 크기 코드(`0x438ce0` 에서 높이 = 기본 `+0x18a`(21) × ½·1·1.5·2·…), 글꼴 바꿈(`+0x19c` → 「Batang」), 굵게·기울임 토글.
- `0x438ce0`: 텍스트 객체 `+0x50` 배열의 `+0x54` 번째 글리프에 vtable[0] 을 부르고 `vt+0x4c(0)`(숨김으로 시작 — 한 글자씩 찍기가 하나씩 보인다). 금칙 문자 표(`0x438dd0`~).
- 배치 `0x4391c0`(가로; 세로는 `0x439530`): 줄마다 x = 펜 `+0x170` + 원점 x(가운데·오른쪽 맞춤 `+0x1a6` 1·2 면 남는 폭을 더함), y = 줄 `+0x174` + 줄 최대 전진 y(=글꼴 높이) − 원점 y, 스프라이트 `vt+0x8c(x, y)`(0x42cd50) 로 자리 지정. 줄 바꿈 = `+0x174 += 최대 높이 + 5`. 칸: `+0x160` 높이 한도, `+0x164` 너비 한도, `+0x168` 왼쪽 여백, `+0x16c` 들여쓰기.

### 2-4. 합성

- 엔진 `[0x466398]`: `+0x9c` 앞 판, `+0xa4` 전환용 판, `+0xb8 + i·20` 장면 묶음, `+0x1a4` 지금 칸.
- `0x43d240`(UpdateDirty): 잠금 `0x43cf60` → 장면 `vt+0x30(앞 판, 사각형)` → 풀기 `0x43cf70` → `0x43d010` → `0x43d0e0`(창 DC 에 그 사각형 BitBlt, 원본 좌표 = 대상 좌표). `0x43d350`·`0x43d3b0` = 장면 `vt+0x34(앞 판)` 전체 합성(+ RepaintAll `0x43d000`).
- 장면 클래스 vtable `0x45b97c`: `+0x30` → 0x435b50 → **0x435220**, `+0x34` → 0x435b60 → **0x435080**. 자식 목록 `[this−0x24]`(12바이트 칸), z 순 색인 `[this−0x1c]`(u16), 개수 `[this−0x20]` 을 돌며 자식 `vt+0x28(dest, clip, offset)`/`+0x2c(dest, offset)`.
- 스프라이트 그리기 **0x42ee40**(thiscall, `ret 0xc`, 머리 `6A FF 68 B8 75 45 00`): 혼합 방식 `+0x28`(0~0x6d, 점프표 `0x42fa24`/`0x42f9bc`)·`+0x30`·`+0x2c`(불투명도) 로 블리터를 고른다. `+0x10` = 더러움 깃발(그리면 0), `+0x4c` = 지난 사각형. 실행 기록: 글리프는 dest = 앞 판 하위 객체 그대로, 자리 = offset + `+0x3c`.
- 앞 판 하위 객체: `+8` 화소(위→아래 800×600 BGRA, 알파 0 — 캡처와 차이 0.015), `+0x14`·`+0x18` 크기.
- `0x43d490`: 앞 판 → `+0xa4` 메모리 간 BitBlt(전환 전 그림 보관). 전환 효과(`0x43e7xx`~`0x43f5xx`)는 이것과 새 그림을 섞어 앞 판에 쓰고 RepaintAll.

### 2-5. 그 밖

- 한 번만 실행: `0x417b60` 이 `OpenMutexA("RSCRIPT")` 가 있으면 −1 로 끝낸다(시험 사본끼리 같이 띄우려고 시험 판에서만 이름을 바꿈).

## 3. 설계(고른 길과 까닭)

늘린 그림에 흐린 1배 글자가 남으면 또렷한 글자 둘레에 번짐이 생긴다. 엔진 판에서 글자를 빼면(글리프를 투명하게) 간단하지만, 전환 효과가 그 판을 복사해 쓰므로 전환 중 글자가 먼저 사라지고, 지도·화면 모듈이 받는 그림도 달라진다. 그래서 **엔진 판은 그대로 두고 화면 모듈로 넘기는 사본만 바꾼다**.

1. 장면 합성(vtable `0x45b97c` +0x30/+0x34)을 「패스」로 감싸고, 그 안의 스프라이트 그리기(0x42ee40)에서 등록된 글리프(혼합 방식 0·2)만 그리기 직전·직후 화소를 적는다.
2. 패스 끝에 앞 판을 역순으로 되감아(직후 → 직전) 「글자 없는 배경」을 만든다. 되감기 직전 화소가 그 글자의 「직후」와 다르면 그 뒤에 다른 것이 덮인 것 → 그 글자(와 겹친 글자)는 원래대로(1배) 둔다. 세이브 화면의 마우스 올린 칸이 이 경우.
3. 글자의 실제 불투명도는 직전·직후·덮임으로 최소제곱으로 잰다 → 한 글자씩 페이드, 창 페이드도 혼합 방식을 몰라도 맞는다.
4. 창으로 가는 BitBlt(IAT `0x459018` 을 engine_bridge 의 bitBlt 앞에 이어 붙임)에서, 늘린 창일 때만 글자 자리를 배경으로 바꾼 사본 판을 넘긴다. 넘기기 전 앞 판의 글자 자리가 패스 직후와 같은지 본다(전환 효과가 바꿨으면 그 글자는 원래대로). 걸친 글자는 통째로 넘긴다.
5. `HiText_Paint` 가 그 글자들을 물리 좌표에 같은 글꼴(굴림/바탕, 높이 × 배율)의 GGO_GRAY8 로 다시 그려 같은 식(`dst += (색 − dst)·덮임·불투명도`)으로 섞는다. 펜·기준선은 1배 값 × 배율, 글자 모양 오프셋만 큰 글꼴 것.
6. 1배 창이면 BitBlt 를 그대로 넘기고 그리지 않는다. 배율이 바뀌면 엔진 RepaintAll 을 한 번 불러 화면 모듈 판의 글자 자리를 새로 받는다.

7. **노란 자막은 「구운 글」**: OVERLAY 처리(`0x41ab1d` → `0x41cd10` → `0x41ba80` → 객체 `[0x466238+n·4]` 의 `0x403870` → `0x4069f0` → `[obj+0x50]` vtable+0x64 = **`0x4082d0`**)가 임시 텍스트 객체(`0x437f60`, 영문 패치가 `0x408311` 에서 `jmp 0x458600` 으로 인자만 바꿈)에 글을 넣고 **`0x438690`(dest, clip, offset)** 으로 자막 스프라이트 자신의 판(예: 232×44)에 글자마다 **`0x42def0`** 으로 한 번 찍은 뒤 임시 객체를 지운다. 이때 글리프 자리는 `+0x3c` 가 아니라 **`+0x1c`·`+0x20`(부모 기준) + offset**(`0x42e540`). 그 뒤 자막 판은 그림 스프라이트로 합성된다(검정 4겹 = 객체 45~48 각자의 판, 노랑 = 49). → 굽기를 부르는 두 곳(`0x4081c2`·`0x408400`)과 글자 찍기(`0x4386fb`)를 감싸 「판 → 글자 목록」을 적어 두고(판 해시로 바뀜 확인), 그 판이 합성될 때 글자 묶음으로 1~6을 그대로 한다.

원래대로(1배) 두는 것: 혼합 방식 1·4·5 글자(TextOutA·회색 판), 세로쓰기, 덮인 글자(세이브 화면 마우스 올린 칸), 전환 효과가 그리는 프레임, 대화 상자(RgnDialog) 글자, 설정·세이브 화면의 그림 글자(애초에 그림).

## 5. 시험 중 고친 결함

- 뒷판 방향: `GetObject(DIBSECTION)` 이 위→아래 DIB 도 `biHeight` 를 양수로 돌려줘 글자가 위아래 뒤집혀 그려짐 → 판마다 (0,0) 한 점을 써 보고 `GetPixel` 로 방향을 잰다.
- 한 글자씩 찍힐 때 글리프가 혼합 방식 2(불투명도 63→255)라 그동안 1배로 보임 → 방식 2 도 받음(불투명도는 재기로).
- F11 로 끈 동안에도 바꿔치기가 돌아 글자가 사라짐 → 켜짐 확인. 배율 바뀔 때 띄우는 스레드가 만든 사본 판(1.9MB)을 안 풀던 것 → 스레드 끝에 풂.
- 노란 자막이 1배로 남음 → 구운 글 경로(7)를 찾아 더함. 굽기 중 글리프 자리는 `+0x1c/+0x20`.
- 화면 모듈이 겹그림 사각형 목록 변화를 비교하므로 `HiText_Rects` 순서를 고정.
- 하네스: 메시지로 보낸 Alt+Shift+숫자는 저장이 됨(시험 사본 0번 칸이 덮였다가 바탕 사본에서 되살림), F11·F12 가 키 표에 없어 「F」 로 가던 것.
